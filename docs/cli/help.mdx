title: facet help
description: Show help for the CLI or a specific command
---

## Usage

```sh
facet --help              # global help
facet help                # the same
facet <command> --help    # one command
facet help <command>      # the same
facet --version           # installed CLI version
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Help or version printed, including `facet help <unknown-topic>`, which falls back to global help. |
| `1` | Unknown command. |
| `2` | An unexpected error escaped command handling. |

## Output

Global help lists every registered command with a short description. Aliases such as `self-upgrade` appear alongside the canonical name. Unimplemented commands are hidden but still resolve for typo suggestions.

Per-command help prints the usage line, description, and available flags. Alias spellings show the canonical command name.

### JSON output

Pass `--json` before or after a command to receive one JSON document on stdout. JSON mode never prompts, opens a browser, or launches an editor. It does not grant consent or overwrite permission. Flags after `--` are positional arguments.

Every command accepts only the options its `--help` lists. An unknown option, an undeclared `--no-<flag>`, a repeated single-value option, or a missing value fails before the command runs, with exit code `1` (or an `INVALID_ARGUMENTS` document under `--json`). Boolean options also accept `--<flag>=true` and `--<flag>=false`. JSON help lists each spelling once; a negative spelling such as `--no-browser` carries `negates`, and a value option carries `valueName`.

```json
{
  "schemaVersion": "3",
  "command": "list",
  "ok": true,
  "data": { "manifestPresent": false, "facets": [] },
  "warnings": []
}
```

Control and invisible characters in strings, including terminal escapes and direction-changing Unicode, are written as `\uXXXX` escapes. A JSON parser returns the exact text; a terminal shows nothing it would act on.

Failures replace `data` with an `error` containing a stable `code`, `message`, and optional `details`, `fix`, and `docsUrl`. Warnings have `code` and `message`. Explicit diagnostics and subprocess errors can appear on stderr. Check the exit code as well as `ok`.

Schema 3 changes existing JSON output: move create, modify, build, update, and outdated success-field reads under `data`. Build failures now expose validation issues under `error.details.issues`; update failures use `error.message` and `error.details.message` instead of `error.what` and `error.detail`.

<Note>
  `--version` is the global version flag only before a command name. After one it belongs to that command, so `facet modify facet --version 1.2.3` sets a facet's version and `facet self-update --version 0.7.0` selects a CLI release.
</Note>
