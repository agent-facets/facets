## Usage

```sh
facet login
```

Signs in by pasting a personal access token from your account at [agentfacets.io](https://agentfacets.io). Requires a terminal.

The token is verified against the registry before it is saved, so a typo or expired token fails immediately and you are reprompted.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Signed in. |
| `1` | Failed, for example no terminal, an invalid token, or a network error. |
| `2` | An unexpected error escaped command handling. |

## Details

### Where the credential is stored

The verified token is written to the [credentials file](/cli/env) with mode `0600`:

```ini
[default]
token = fct_pub_xxxxxxxxxxxxx
```

### Token precedence

`FACET_TOKEN` takes precedence over the saved file. `facet login` says so when both are present, so the variable cannot silently shadow what you just saved.

## Troubleshooting

<AccordionGroup>
  <Accordion title="not signed in, no registry credential found">
    **Cause:** a command that needs the registry found neither `FACET_TOKEN` nor a saved credentials file.

    **Fix:**

    ```sh
    facet login                    # interactive
    export FACET_TOKEN=fct_pub_…   # or this, in CI
    facet whoami
    ```
  </Accordion>

  <Accordion title="your registry credentials could not be read">
    **Cause:** the credentials file exists but is unreadable or malformed. This is a different failure from having no credential at all.

    **Fix:** run `facet login` again to rewrite the file, or set `FACET_TOKEN` for the current shell.
  </Accordion>

  <Accordion title="the token was rejected">
    **Cause:** the registry refused the pasted token, usually because it was revoked, expired, or copied incompletely.

    **Fix:** mint a new token in your account settings and paste it again.
  </Accordion>
</AccordionGroup>
