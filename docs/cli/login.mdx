## Usage

```sh
facet login [--browser | --no-browser | --token]
```

In a terminal, choose browser sign-in or paste a personal access token. Browser sign-in is available on macOS and Linux. On Windows, use `facet login --token` or [`FACET_TOKEN`](/cli/env#facet_token).

The registry verifies your identity before the CLI saves a usable credential. For CI and scripts, supply `FACET_TOKEN` instead of running interactive login.

## Examples

```sh
facet login --browser      # open the verification page
facet login --no-browser   # show the URL and code for another browser
facet login --token        # paste a personal access token in a terminal
facet whoami
```

## Flags

<ResponseField name="--browser" type="boolean">
  Start browser sign-in and try to open the verification page. The URL and code are always printed, so you can finish manually if opening the browser fails.
</ResponseField>

<ResponseField name="--no-browser" type="boolean">
  Start the same sign-in flow without opening a browser. Open the printed URL on a device with a browser and enter the code while the command waits.
</ResponseField>

<ResponseField name="--token" type="boolean">
  Paste a personal access token from your account at [agentfacets.io](https://agentfacets.io). Requires an interactive terminal and cannot be combined with a browser flag.
</ResponseField>

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Succeeded. |
| `1` | Failed in an anticipated way, such as cancellation, expired verification, rejected credentials, or a network error. |
| `2` | An unexpected error escaped command handling. |

## Output

Browser sign-in prints a verification URL and user code, then `Logged in as yourname.` after verification succeeds. Press Ctrl+C to cancel. A pasted token also prints your account tier after it is verified.

## Details

### Browser verification

Confirm the code shown in your terminal on the verification page. Complete any registry account setup requested in the browser, then sign in again if the CLI asks you to finish onboarding.

This uses the [OAuth device authorization flow](https://workos.com/docs/authkit/cli-auth), with a public client ID and no embedded API key or client secret. The CLI does not need a browser redirect back to your machine. It accepts only the selected registry's validated sign-in configuration and rejects unexpected authentication redirects.

### Where the credential is stored

See [browser credential storage and registry binding](/cli/env#browser-credentials).

A verified personal access token is written to the [credentials file](/cli/env#facet_dir):

```ini
[default]
token = fct_pub_xxxxxxxxxxxxx
```

### Token precedence

Commands select the first available credential in this order:

1. Non-empty `FACET_TOKEN`.
2. A saved personal access token.
3. A browser session for the selected registry.

Login warns when a personal access token shadows your new browser session. Unset `FACET_TOKEN` and remove a saved token with [`facet logout`](/cli/logout) before using browser sign-in. Removing a saved token can reveal an existing browser session.

A rejected or unreadable selected credential fails the command. The CLI does not switch to another identity or retry anonymously after an authentication failure.

### Session renewal

Commands renew browser sessions when needed and verify the registry identity before using them. A temporary network or registry verification outage fails the command while preserving local sign-in state; retry when connectivity returns.

An expired or revoked session requires browser sign-in again. If a refresh outcome cannot be confirmed within the safe retry window, the CLI stops renewing it and asks you to sign in again rather than replaying an old refresh indefinitely.

## Troubleshooting

<AccordionGroup>
  <Accordion title="browser sign-in did not complete">
    **Cause:** verification expired, was denied, or was cancelled.

    **Fix:** start `facet login --browser` or `facet login --no-browser` again and complete the new verification prompt.
  </Accordion>

  <Accordion title="registry account setup is required">
    **Cause:** browser authentication succeeded, but registry onboarding is incomplete.

    **Fix:** open the onboarding page reported by the CLI, finish setup, then sign in again.
  </Accordion>

  <Accordion title="local sign-in state could not be read or updated">
    **Cause:** your [browser credential storage](/cli/env#browser-credentials) failed its safety checks.

    **Fix:** check the [local state requirements](/cli/env#browser-credentials), correct ownership and permissions, then retry. The CLI will not weaken these checks to save credentials.
  </Accordion>

  <Accordion title="your registry credentials could not be read">
    **Cause:** the personal access token file exists but is unreadable or malformed.

    **Fix:** check its permissions, run `facet login --token` to replace it, or set `FACET_TOKEN` for the current shell.
  </Accordion>

  <Accordion title="the token was rejected">
    **Cause:** the registry refused the pasted token, usually because it was revoked, expired, or copied incompletely.

    **Fix:** mint a new token in your account settings and paste it again with `facet login --token`.
  </Accordion>
</AccordionGroup>
