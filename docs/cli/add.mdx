title: facet add
description: Add facets to a project and install them
---

## Usage

```sh
facet add <source> [more sources...]
```

Adds the named facets to `facets.json` and installs them into every connected adapter. There is no separate install step afterwards.

Specifiers are validated before anything touches disk. If the project has no adapter, a terminal gets the picker and a non-interactive run fails pointing at [`facet adapter add`](/cli/adapters/add). From there the run is an ordinary [install](/cli/install), so it reports the same outcomes and can meet the same [collision](/cli/install#name-collisions) and [MCP approval](/cli/install#mcp-servers) screens.

A facet whose only asset is an MCP server is valid: it configures servers and writes no files. A facet that composes other facets with a non-empty `facets` array is rejected.

## Examples

```sh
facet add viper-plans                    # bare name, pins the resolved version
facet add viper-plans@1.*                # wildcard, floats within 1.x
facet add @acme/deploy-tools             # scoped facet
facet add github:agent-facets/viper-plans#main
facet add ./local-facets/my-plans
facet add viper-plans rezi planner@2.*   # several at once
```

## Flags

<ResponseField name="--verbose" type="boolean">
  Show detailed step output on stderr. Declaration contents never appear here. See [where declarations appear](/cli/install#where-declarations-appear).
</ResponseField>

<ResponseField name="--accept-mcp" type="boolean">
  Approve the [MCP configuration](/cli/install#accept-mcp) this run would write, without prompting.
</ResponseField>

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Add and install succeeded. |
| `1` | Failed, for example a parse error, no usable adapter, an unresolved [collision](/cli/install#name-collisions), unapproved MCP configuration, or an install failure. |
| `2` | An unexpected error escaped command handling. |

Nothing is written unless the run had already started writing, in which case it is rolled back.

## Details

### Source grammar

#### Registry names

<CodeGroup>

```sh Bare name
facet add viper-plans
# resolves to the newest release, then pins that exact version
# in facets.json
```

```sh Exact version
facet add viper-plans@1.2.3
# written verbatim
```

```sh @latest
facet add viper-plans@latest
# re-resolves each install; "latest" is preserved, so the entry
# keeps floating. Only a bare name pins.
```

```sh Wildcard
facet add viper-plans@1.*
# also 1.2.* and *. The wildcard stays in facets.json and the
# resolved version goes in the lockfile.
```

```sh Scoped
facet add @scope/name@1.2.3
# the leading @ marks the scope, a later @ separates the version
```

</CodeGroup>

#### Git and GitHub sources

<CodeGroup>

```sh GitHub shorthand
facet add github:owner/repo#ref
# optional #ref: branch, tag, or SHA
```

```sh Schemed URL
facet add https://host/repo.git#ref
# https, http, ssh, and git schemes are accepted
# a schemed URL must end in .git
```

```sh SCP-style URL
facet add git@host:owner/repo.git#ref
# standard user@host:path SSH form, with no .git requirement
```

</CodeGroup>

A git source is cloned and built locally, so `git` must be on your `PATH`.

#### Local paths

```sh
facet add ./facets/my-plans
# relative or absolute, and must resolve inside the project tree.
# A file: prefix is tolerated and stripped.
```

A `~` is not expanded by the CLI. Let your shell expand it, and remember the result still has to sit inside the project tree.

#### Forms that are rejected

```sh
facet add git+https://host/repo.git  # drop the git+ prefix
facet add ftp://host/repo.git        # unsupported scheme
facet add https://host/repo          # schemed URL must end in .git
facet add viper-plans@^1.2.3         # caret and tilde ranges: use 1.*, 1.2.*, or 1.2.3
facet add viper-plans@">=1.0.0"      # comparator and OR ranges
facet add "viper-plans@1.0.0 - 2.0.0"  # hyphen ranges
facet add viper-plans@1.x            # x placeholders: use 1.* or 1.2.*
facet add viper-plans@1.2.3-rc.1     # prerelease and build metadata
facet add @scope                     # incomplete scoped name
facet add acme/foo/bar               # too many path segments
```

### Re-adding a facet

Re-adding pins one facet to a version you name. To move every declared facet to newer releases, use [`facet update`](/cli/update) instead.

- **Same source**: a no-op, reported as `unchanged` or `repaired`. If you aliased or omitted one of its contributions since, it reports `updated`.
- **Different version**: updates the entry and counts under `N updated`. Per-facet version transitions are printed by `facet update`.
- **Bare re-add**: resolves the newest release and pins it, even over an existing wildcard.
- **Explicit `@latest` or wildcard**: re-resolves to the newest match and keeps floating.

Recorded [materialization overrides](/specification/materialization#recording-intent) are preserved across a re-add, for text assets and servers alike. An override naming something the new version no longer contains is dropped, and the install tells you which. Under [`--frozen-lockfile`](/cli/install#frozen-lockfile) that same stale override is blocking drift instead.

What gets written per specifier shape is defined by the [manifest write policy](/specification/install#manifest-write-policy). A successful non-frozen add also stamps `"manifestVersion": 0.2`.

## Troubleshooting

<AccordionGroup>
  <Accordion title="a source specifier was rejected">
    **Cause:** the specifier does not match the [source grammar](#source-grammar). Every specifier is parsed before any network or disk work, so the run stops with the project untouched.

    **Fix:** the error names the offending specifier and the accepted forms. See [forms that are rejected](#forms-that-are-rejected) for the common substitutions.
  </Accordion>

  <Accordion title="git is not installed">
    **Cause:** a git or GitHub source is cloned locally, and `git` was not found on your `PATH`.

    **Fix:** install git, or add the facet from the registry or a local path instead.
  </Accordion>

  <Accordion title="a git source needs authentication">
    **Cause:** the repository is private, or the clone prompted for credentials.

    **Fix:** use a public repository, or an SSH URL backed by a running SSH agent. Interactive credential prompts are not supported during a clone.
  </Accordion>

  <Accordion title="a git ref could not be checked out">
    **Cause:** the branch, tag, or commit named after `#` does not exist in the cloned repository.

    **Fix:** correct the ref, or drop it to use the default branch.
  </Accordion>

  <Accordion title="a local path resolved outside the project">
    **Cause:** a local source must resolve inside the project tree, so a facet cannot be installed from an arbitrary location on your machine.

    **Fix:** move or copy the facet into the project, then add it by a path inside the tree.
  </Accordion>

  <Accordion title="the facet declares composition">
    **Cause:** the source declares a non-empty `facets` array. Composition is reserved in the manifest format and is not installable yet.

    **Fix:** ask the publisher for a release that ships its own assets directly. There is no flag to install it as-is.
  </Accordion>

  <Accordion title="a git or local source failed to build">
    **Cause:** the clone or directory resolved, but its `facet.json` did not load, its name disagreed with what you asked for, or the build failed.

    **Fix:** run [`facet build --verify`](/cli/authoring/build) inside that source to see the validation errors, then fix and re-add.
  </Accordion>
</AccordionGroup>
