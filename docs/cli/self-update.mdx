title: facet self-update
description: Update the facet CLI to a newer version

## Usage

```sh
facet self-update
```

Updates the `facet` binary in place. `facet self-upgrade` is an alias.

It detects how the binary was installed and dispatches to that mechanism, so download, verification, and the swap are handled by the installer or package manager you already used. It never reads or writes `facets.json`, `facets.lock`, or any materialized asset. To move the facets a project declares, use [`facet update`](/cli/update).

## Examples

```sh
facet self-update                  # update to the latest published version
facet self-update --version 0.7.0  # pin to a specific version
facet self-update --dry-run        # preview without changing anything
```

## Flags

<ResponseField name="--version <x.y.z>" type="string">
  Install a specific version instead of the latest.
</ResponseField>

<ResponseField name="--dry-run" type="boolean">
  Print the plan and modify nothing.
</ResponseField>

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Updated, already current, a completed `--dry-run`, or manual mise or Homebrew guidance printed. |
| `1` | Dev-mode refusal, an unsupported Homebrew version request, network error, or malformed registry data. |
| `2` | An unexpected error escaped command handling, or the installer exited `2`. |
| other | Passed through from the underlying installer or package manager. |

This is the one command whose codes are not exclusively its own: it dispatches to the installer or package manager you used, and returns whatever that returns. Treat any non-zero code as a failure and read the output rather than branching on the number.

## Output

A `--dry-run` names the current and target versions, the detected install method, and the exact command that would run.

## Details

### Install methods

The update path follows how the binary was installed: the curl installer, an `npm`, `yarn`, `pnpm`, or `bun` global install, a verified [mise install](#mise-installs), or a verified [Homebrew install](#homebrew-installs).

If the location cannot be classified, self-update falls back to the curl installer and warns when `facet` on your `PATH` still resolves elsewhere afterwards, so you can remove the older copy or reorder your `PATH`.

### Mise installs

Starting with Facet 0.36.4, self-update supports mise installations using `github:agent-facets/facets` with `version_prefix=agent-facets@`. See [Install with mise](/guides/install-with-mise) for setup.

```sh
facet self-update --dry-run
facet self-update
```

The update preserves the existing mise configuration file and backend options, whether the installation is global, project-local, or uses a custom config path. A preview shows `mise use --path` with that config path and the target version.

If mise owns the binary but its provider, options, or configuration cannot be verified, self-update prints manual guidance without changing the configuration or invoking another installer. This guidance currently exits with `0`; read the output to distinguish it from a completed update.

### Homebrew installs

When Homebrew verifies that it owns the running binary from `agent-facets/tap/facet`, self-update does not contact npm or replace the binary. It prints the Homebrew commands to run:

```sh
brew update
brew upgrade agent-facets/tap/facet
```

`facet self-update --version <x.y.z>` exits with `1` for a Homebrew install because `brew upgrade` cannot request an arbitrary Facet version.

If Homebrew may own the binary but the formula cannot be verified, self-update prints inspection guidance and does not fall back to another installer.

### Environment

`FACET_CLI_REGISTRY` sets the npm registry used to look up CLI versions. It is not the facet registry, which is `FACET_REGISTRY_URL` and has no effect here. See [environment variables](/cli/env).

## Troubleshooting

<AccordionGroup>
  <Accordion title="self-update refuses in dev mode">
    **Cause:** `FACET_BIN_OVERRIDE` is set, so you have taken control of which binary runs. Self-update will not write over the path you pointed at.

    **Fix:** unset `FACET_BIN_OVERRIDE` to update a real install.
  </Accordion>

  <Accordion title="the update ran but facet still reports the old version">
    **Cause:** another copy of `facet` comes first on your `PATH`, which happens after a fallback install.

    **Fix:** the warning names both paths. Remove the older copy, or reorder your `PATH`.
  </Accordion>

  <Accordion title="the version list could not be read">
    **Cause:** the npm registry was unreachable, or returned data the CLI could not parse.

    **Fix:** check connectivity and retry. If you point `FACET_CLI_REGISTRY` at a mirror, confirm it serves the `agent-facets` package.
  </Accordion>

  <Accordion title="mise could not be safely updated automatically">
    **Cause:** mise owns the running binary, but installation metadata is unavailable, invalid, or identifies an unsupported provider or version prefix.

    **Fix:** inspect `mise which facet --plugin` and your existing mise configuration. Update the Facet entry in that same file manually, preserving its provider, options, and scope. Do not replace it with an unscoped `mise use` command from an unrelated directory. See [supported mise installs](#mise-installs).
  </Accordion>
  <Accordion title="Homebrew could not be safely identified">
    **Cause:** the running binary is under Homebrew's Cellar, but Facet could not verify that the official formula owns it.

    **Fix:** run `brew which-formula "$(command -v facet)"` to identify the owning formula, then update that formula through Homebrew. Do not run another Facet installer until you know which binary your shell uses.
  </Accordion>
</AccordionGroup>
