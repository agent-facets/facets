A skill is a directory bundle holding domain knowledge the assistant applies passively: conventions, checklists, best practices. Skills follow the [Agent Skills](https://agentskills.io/specification) specification.

Each skill lives at `skills/<name>/SKILL.md` and is declared in `facet.json` under `skills`. Placement and descriptor rules live at [Text assets](/specification/manifest#text-assets).

## Example

```markdown expandable skills/code-review/SKILL.md
# Code Review

## Structure
- Check that new files are placed in the correct directory.
- Verify imports are sorted and unused imports are removed.

## Logic
- Look for off-by-one errors in loops and array access.
- Verify error handling covers all failure paths.
- Confirm discriminated unions are exhaustively matched.

## Testing
- Every new public function should have a corresponding test.
- Cover edge cases: empty input, null, boundary values.

## Style
- Prefer `const` when the binding is never reassigned.
- Use early returns to reduce nesting.
```

## Companion files

A skill can ship more than its `SKILL.md`. Declare companion files in the descriptor's `files` array, as paths relative to the skill directory:

```json facet.json
{
  "skills": {
    "code-review": {
      "description": "Code review guidelines",
      "files": ["references/style-guide.md", "scripts/lint.ts"]
    }
  }
}
```

Companions install and remove atomically with the skill. Files you add to a skill directory yourself are left in place on removal. A companion cannot be `SKILL.md`. See [Supplementary files](/specification/manifest#supplementary-files).

## When to use skills

Use a skill for knowledge the assistant should always have: coding standards, review checklists, domain guidelines, framework practices.

Use an [agent](/docs/learn/agents) to define a persona. Use a [command](/docs/learn/commands) for something the user invokes.
