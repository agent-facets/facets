Make adapter installation and loading compatibility-aware via adapter API `0.0`. `facet adapter install` now accepts version selectors (`name@1.2.3`, `name@1.*`, `name@1.2.*`, `name@*`, `name@latest`) and selects the highest stable npm release whose `facetAdapterApiVersion` this CLI supports — an exact version that is incompatible fails rather than substituting another release, and npm range syntax (`^`, `~`, comparators) is rejected with the accepted forms. Installations use a managed layout (`installation.json` receipt + immutable generations) with staged verification and atomic activation: any failure before activation leaves the existing installation untouched. Installed adapters are inspected before use — `facet build`, `facet add`, `facet remove`, and `facet install` fail closed on incompatible or broken adapters, before any adapter method runs or project files change, with per-adapter diagnostics and the exact reinstall command. `facet adapter list` shows each adapter's declared API and support status. Local and git adapter sources now bundle build-first, running a dependency install only when the optimistic build fails. Previously installed bundles predate API declarations and require a one-time `facet adapter install <name>` after updating.
